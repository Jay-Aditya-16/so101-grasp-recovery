# Phase III: ablation, implementation, and research plan

## What we measured

The [ablation](phase3-ablation-analysis.md) compares the fixed ACT policy, retry and object-aware recovery on historical simulator cases. It also reproduces 24 IK calls at seed 1030: no original transfer solution met the existing endpoint and orientation checks. On this case the camera estimate was about 2.07 mm from simulator position at the fresh observation, and the cube was lifted about 97.6 mm. These are stage observations from one case, not a general perception or grasp success rate. The prior placement bandit cannot help when no feasible candidate is generated.

## Implemented: opt-in tilted IK search

The original IK candidate ordering and gates remain the default. With `--experimental-cone-ik`, if the original transfer or release search fails, the simulation controller tries explicit tool axes around a 40-degree cone while retaining the existing 5 mm position bound, 0.70 minimum down-axis dot, joint-limit check and sampled arm-path check. The cone direction is `[sin(40°)cos(phi), sin(40°)sin(phi), -cos(40°)]`; it has unit length and down-axis dot `cos(40°)=0.7660`, greater than 0.70. A solved pose must independently pass forward kinematics; the requested direction is not assumed to equal the realized direction.

At the recorded 1030 state, the +Y cone candidate had FK error 3.41 mm and down dot 0.7660, passed the existing sampled arm-path test, and passed a **separate offline** 101-sample ideal rigidly attached cube/environment check. The latter uses privileged simulator state, assumes no slip, and is not part of the controller. See [IK diagnostic](phase3-ik-diagnostic.md). The gate still does not verify forces, actual grasp retention, dynamics or continuous carried-object clearance. This is a simulation experiment only, not a physical-arm controller.

A live run on the **development seed 1030 used to design this fallback** lifted and placed the cube; the original and frozen-bandit variants had lifted but failed placement. This is a tuned example, not an independent success estimate. A further predeclared seed 1031 was run in cone-then-original order: both placed and the cone variant never needed the fallback. One untouched pair cannot establish equivalence or generalization; the order was predeclared but not randomized. Both studies use the same fixed cube, scene, checkpoint, horizon and recovery settings. Strict placement is a simulator proxy, not a real-world stability guarantee.

MATLAB R2025b reapplied the 0.70 dot and 5 mm position gates to 20 stored FK results and agreed with Python on all 20. This checks threshold arithmetic given stored FK values; it is not an independent forward-kinematics, swept-volume or physics validation. Raw local trajectory archives, compact summaries, the predeclared 1031 plan, MATLAB output and capture validation are described in `reports/phase3-cone-validation/`.

Run the experimental version in a live viewer using the command in `docs/phase3-placement-bandit.md`, replacing its bandit flags with `--experimental-cone-ik`. Do not use it with physical hardware. Further held-out, matched tests must record planner wall-clock latency, all candidate rejections, object drop/slip, collisions, unsuccessful and interrupted trials, and test carried-object swept paths before widening scope.

## Implemented: grasp-stage data preparation

`scripts/extract_grasp_outcomes.py` extracts offline grasp-stage proxies from saved trajectories. A completed recovery lift check receives label 1 only if the recorded simulator cube rises at least 5 cm from its position at closing and bilateral contact occurs somewhere in the closing-to-check window; a completed check without both gets 0. A missing recovery grasp, interrupted viewer, or missing lift check is unlabelled. Contact and lift need not be simultaneous, so the proxy does not prove a stable grasp. Labels use privileged simulator state exclusively offline and are not available as controller observations. Dataset rows include capture hashes to identify repeats; paired runs with the same seed must not be counted as independent data. Existing selected recordings provide positives but do not provide enough diverse, separately labelled failed grasps or actual alternative grasp candidates to validate grasp learning.

## Next implementation gates

1. **Physical planning and measurement:** add online-checkable carried-object geometry, stronger grasp/hold evidence, continuous or higher-resolution collision analysis, and measured planning latency. Keep failures and no-candidate outcomes in the denominator. Perform controlled predeclared multi-seed tests with order randomized and equal conditions.
2. **Grasp-specific learning:** generate a small, meaningful set of object-relative grasp configurations with validated IK, path and visibility; derive a reliable grasp outcome signal and gather genuine successful and failed attempts. Compare fixed order, random feasible choice and a [BORGES](https://proceedings.mlr.press/v155/danielczuk21a.html)-inspired pose-conditioned bandit under matched conditions. The current placement bandit and offline lift proxy are not BORGES and do not establish one-shot grasp learning.
3. **World-model experiment:** separately test action-conditioned future prediction on episode-separated two-view SO-101 data against persistence and action-shuffling baselines. [V-JEPA 2](https://arxiv.org/abs/2506.09985) and its action-conditioned variant are research references; cross-robot action mapping and L4/M1 memory and latency are unverified. [LeWorldModel](https://arxiv.org/abs/2603.19312) is a smaller possible benchmark. Do not connect any model to control without evidence it improves held-out closed-loop outcomes within the same safety checks.

See [model research](phase3-model-research.md), [ablation](phase3-ablation-analysis.md) and [learning maths](phase3-learning-math.md) for primary references and experimental design. None of the current work establishes consciousness or guaranteed lifelong learning.
